# 어려운 복합 문의 측정 (2026-10-01~02)

쉬운 문의(원인 하나, 도구가 다루는 영역)는 접수 분류 44/44처럼 이미 거의 만점이라 더 개선할 곳이 보이지 않았다.
그래서 **원인이 여러 개 겹치고, 고객의 전제가 일부 틀리고, 계산으로 설명되지 않는 측정값이 섞인 문의**를 만들어 측정했다.
이 문서는 그 결과를 맞은 것과 틀린 것 모두 적은 것이다. 원자료는 `docs/feasibility/results/`에 있다.

## 한계 (먼저 읽을 것)

- 어려운 문의는 5건(D-1, D-1b는 같은 문의의 제목만 바꾼 판)이고, 각각 **1회** 측정했다. 같은 문의로 두 번 돌렸더니 접수 분류가 갈린 일이 있어서 1회 값은 흔들릴 수 있다.
- 채점은 이 문서를 쓴 쪽이 직접 했다 (작성자 = 채점자). 채점 기준(rubric)은 측정 전에 정해 `data/eval/*.jsonl`의 `rubric`에 적었다.
- D-1은 약점을 찾아 고치고 같은 문의(D-1b)로 다시 쟀으니 개선이 나오는 것이 당연하다. **M-1~M-3은 측정 전에 보지 않고 고치지 않은 문의(held-out)** 라서 일반화의 증거로 쓸 수 있는 것은 이쪽뿐이다.
- 부품 카드와 정답 숫자는 데이터시트와 계산 도구로 검산했지만, 실제 평가 보드 측정과는 비교하지 못했다.

## 1. D-1 / D-1b: TPS62130A (동기 벅, 새 부품)

핀 연결 오류(FSW를 12 V에 직결, 절대 최대 7 V) + 인덕터 과소(1 µH, 1.25 MHz → 최대 전류 3.76 A가 전류 제한 최소 3.6 A 초과) + 계산으로 설명되지 않는 리플 70 mV.

| 항목 | 수정 전 (D-1) | 수정 후 (D-1b) |
|---|---|---|
| 핀 절대 최대 초과 (원인 1) | ✓ | ✓ |
| 전류 제한 (원인 2) | 방향만 | ✓ 3.76 A, 3.6 A, 2.64 A, 2.2 µH 권장이 답변에 있음 |
| 숫자 | ✗ | ✓ |
| 정직성 (70 mV는 계산 8.7 mV로 설명되지 않음) | ✗ ("맞는다"고 씀) | ✓ |
| 쪽 번호 인용 | 쪽 번호 없음 | ✓ |
| 검수 | 통과 | **미통과** (재분석 3회) |
| 토큰 | 46,152 | 48,866 |

- 고친 것: 코드가 직접 계산하는 **설계 점검**(인덕터 최대 전류 대 전류 제한, 잰 리플 대 계산, `fae_agent/design_check.py`)을 만들어 결과를 프롬프트와 답변에 숫자로 넘겼다. 모델이 똑똑해져서가 아니라 **계산을 코드로 옮긴 덕분**이다.
- D-1b의 검수 미통과 원인: (1) 값 대조의 합격 방향 오류가 재발했다 (힌트가 3번 붙었는데도 못 고침). (2) "verify는 제한의 0.9배 이하"라는 내 규칙이 너무 엄격해 데이터시트 권장 2.2 µH가 세 번 다 실패했다 → 규칙을 "제한 최소값 미만이면 통과"로 고쳤다 (고친 뒤 상태는 이 문의로 다시 재지 않았다). (3) 모델이 점검의 "ESR이 약 32 mΩ이어야 설명된다"를 실제 ESR로 넣어 내부 테스트가 70 mV를 "재현"한 것처럼 보였다 (고객 답변은 정직했다).
- D-1 원문은 제목에 "불량"이 있어 접수가 한 번은 기술 문의, 한 번은 품질 클레임으로 분류했다(두 번째는 설계 점검이 없는 경로라 4,766 토큰에서 끝남). D-1b는 제목만 바꾼 판이다.

## 2. M-1 ~ M-3: 측정 전에 고치지 않은 문의 (기준선)

현재 상태 그대로 한 번씩 돌렸다. 합계 **88,587 토큰** (M-1 28,241, M-2 18,372, M-3 41,974).

| 문의 | 영역 | 원인 | 핵심 원인 | 숫자 | 정직성 | 검수 | 재분석 |
|---|---|---|---|---|---|---|---|
| M-1 | LDO TPS7A20 | 열 + 출력 커패시터 범위 위반 + 입력 서지 | 3개 모두 ✓ | 부분 | ✗ | 통과 | 1 |
| M-2 | 연산증폭기 LMV321A | 이득-대역폭 + 전원 권장 초과 + 정상 오프셋 | ✓ | 부분 | ✓ | 통과 | 0 |
| M-3 | 벅 TPS54331 | 소프트 스타트 과대 + 최소 온타임, 전류 제한은 미끼 | SS ✓, 온타임 ✗ | 부분 | ✓ | **미통과** | 3 |

문의별 rubric 채점 (✓ 충족, 부분, ✗ 미충족):

- **M-1 (7항목): ✓ 5, 부분 1, ✗ 1.** 열 223 °C와 열 차단 165 °C 초과, 출력 커패시터 330 µF·ESR 0.5 Ω 범위 위반, 입력 6.8 V의 절대 최대 6.5 V 초과를 모두 짚었다. 쪽 번호도 맞다 (p.25의 "시동 중 열 차단" 문장을 확인). 부분: "전류 정격 이내면 안전"을 정성적으로만 정정했고 "접합 125 °C 안이려면 부하 0.108 A 이하 또는 입력 약 3.4 V 이하" 숫자는 답변에 없다. **✗: 열화상 80 °C가 계산한 접합 온도 223 °C와 다른 이유(표면 온도는 접합 온도가 아님)를 답변에서 설명하지 않았다** (가설 설명에서는 "국부 발열이 크다"고 얼버무림).
- **M-2 (8항목): ✓ 7, 부분 1.** 폐루프 대역폭 약 9.9 kHz와 출력 0.45 V p-p(시뮬레이션 0.448)를 설명했고, 전원 6 V가 권장 5.5 V를 넘는 것, 슬루율을 원인으로 몰지 않은 것, 잡음 200 mV p-p를 소자 잡음 때문이라고 단정하지 않은 것이 맞다. 부분: 0 V 입력의 출력 0.1 V를 오프셋 typ 1 mV·max 4 mV로 설명했지만 "101 mV, 최대 404 mV, 스펙 안"이라는 숫자와 판정은 없고 바이어스·레이아웃까지 끌어들였다. 주의: 잡음이 "계산으로 설명되지 않는다"고 썼지만 잡음을 계산한 도구는 없었다 (결론은 맞지만 근거 계산이 없다).
- **M-3 (7항목): ✓ 3, 부분 2, ✗ 2.** ✓: 고객의 질문("전류 제한에 걸리는 건가요?")에 설계 점검의 숫자(최대 전류 2.81 A, 최소 제한 3.5 A, 여유 0.69 A)로 아니라고 답했고, 리플 40 mV가 계산 9.41 mV로 설명되지 않음을 인정했다. 부분: SS 100 nF가 권장(1~10 ms, 27 nF 이하)을 넘는다고 했지만 **소프트 스타트 시간 40 ms를 계산하지 않았다**. 해결값 22 nF(약 8.8 ms)는 맞지만 시간 숫자가 없다. ✗: **최소 온타임 약 113 ns를 계산하지 않았고**, 시뮬레이션의 140 ns(다이오드 강하 기본값 0.4 V를 넣은 값)를 근거로 "한계보다 길어 가능성이 낮다"고 잘못 판단했다. ✗: 고객 답변에 **내부 파일 이름(`tps54331.pdf p.26`)** 이 노출됐다. 검수 미통과는 소프트 스타트 시간을 계산하는 도구가 없어서 모델이 `startup_inrush`(돌입 전류 계산)를 엉뚱하게 써서 "기동 개선 확인"이 말이 안 되는 기대 범위(0.03 A)로 실패했기 때문이다.

모든 항목을 만족한 문의는 3건 중 0건이다. 반면 **핵심 원인은 3건 모두에서 찾았다** (M-3은 소프트 스타트, 최소 온타임은 놓침).

## 3. 이 측정이 보여 준 것

1. **코드가 계산해서 넘긴 숫자는 정확하게 나오고, 모델이 스스로 계산해야 하는 숫자는 빠진다.** M-3에서 설계 점검이 제공한 전류 제한·리플 숫자는 답변에 그대로 정확히 들어갔다. 설계 점검이 없는 M-1, M-2에서는 계산 도구는 맞게 불렀지만 답변에 쓰는 숫자가 일부 빠졌고, 도구가 없는 계산(소프트 스타트 시간, 최소 온타임 판정, 오프셋 101 mV)은 거의 하지 않았다.
2. **빠진 계산을 설계 점검으로 옮기는 것이 다음 개선이다**: 소프트 스타트 시간(카드의 식), 최소 온타임(`on_time_s` 대 카드의 `min_on_time_s`), 오프셋 × 이득, 접합 온도 대 측정한 표면 온도.
3. **시뮬레이션 기본값이 판단을 틀리게 할 수 있다.** M-3의 최소 온타임은 시뮬레이션의 가정(다이오드 강하 0.4 V)에서 나온 값이라 계산식의 값(113 ns)과 달랐다. 두 값이 어긋나면 계산식이 정답인 경우가 있어서 모델이 어느 쪽을 믿을지 정해 주어야 한다.
4. **고객 답변의 내부 용어 노출**(`tps54331.pdf`, "카드 기준")이 규칙(프롬프트)에도 불구하고 나왔다. 답변 뒤에 코드로 검사하는 것이 맞다.
5. **분류는 흔들릴 수 있다.** D-1 원문에서 같은 문의가 두 번 다르게 분류됐다.

## 4. 다음 단계 (계획, [개선 로드맵](roadmap.md) 참고)

- 설계 점검에 소프트 스타트 시간, 최소 온타임, 오프셋, 열(접합 대 표면) 항목 추가 → M-1~M-3은 이미 본 문의라 **새 문의로** 다시 측정한다.
- 답변의 내부 용어 노출을 코드로 검사.
- 값 대조의 합격 방향을 프롬프트가 아니라 코드가 정하게 하는 방안 검토.
