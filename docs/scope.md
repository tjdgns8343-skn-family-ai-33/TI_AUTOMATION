# 범위 결정

## 결론

컴플레인은 두 종류로 나눠서 다룹니다. 이 프로젝트의 메인은 **기술 문의형**입니다.

| 유형 | 예 | 이 프로젝트에서 하는 일 |
| --- | --- | --- |
| **기술 문의형 (메인)** | 출력 발진, 과열, 리플·노이즈, 전원이 안 켜짐, 출력 전압 이상, 통신 오류 | 문서 근거 검색 → 원인 가설 3개 → 계산·시뮬레이션으로 재현·해결책 확인 → 검수 → 답변 초안 → 사람 승인 |
| 품질 클레임형 | 불량 반품, 파손, 수량 불량 | CPR(반품) 필수 자료 체크리스트와 8D 보고서 초안까지 |
| 배송·기타 | 납기, 주문, 샘플 | 분류해서 담당 부서로 넘기는 답변 초안까지 |

## 왜 기술 문의형이 메인인가

- 대부분 고객의 **회로 설계나 사용 조건** 문제입니다. 부품 불량이 아니라 커패시터 선택, 방열, 풀업 저항, 입력 전압 같은 조건 문제라서
  데이터시트·앱노트(문서), 설계 공식(계산), ngspice(시뮬레이션)로 풀 수 있습니다.
- 결과를 **숫자로 검증**할 수 있습니다. 고객 조건으로 증상이 재현되는지(reproduce), 해결책을 적용하면 목표를 만족하는지(verify)를 확인하고,
  평가셋으로 분류 정확도와 원인 적중률을 잴 수 있습니다.
- 품질 클레임은 실물 불량 분석(FA)이 핵심이라 장비와 실물 없이는 결과를 검증할 수 없습니다. 그래서 자료 점검과 보고서 초안에서 멈춥니다.

## 증상 코드 (`fae_agent/schemas.py`의 `SYMPTOM_CODES`)

| 코드 | 뜻 | 주로 쓰는 테스트 |
| --- | --- | --- |
| oscillation | 출력 발진·링잉 | LC 공진 계산, 부하 스텝 시뮬레이션 |
| ripple_noise | 리플·노이즈 | 벅 리플 계산 |
| overheating | 과열 | 접합 온도 계산 (LDO·벅) |
| wrong_output | 출력 전압 이상 | 피드백 분압 계산, 전류 제한 확인 |
| startup_fail | 기동 실패·전원이 안 켜짐 | 돌입 전류 계산 |
| communication | 통신 오류 (I2C 등) | 풀업 저항·상승 시간 계산 |
| damage | 파손·타버림 | 품질 클레임 쪽으로 분류 |

## 범위 밖

- TI 사이트 자동 수집(스크래핑·크롤링), E2E 포럼 크롤링 ([data_policy.md](data_policy.md))
- 실제 고객 데이터
- 암호화된 TI SPICE 모델 시뮬레이션 (PSpice for TI·TINA-TI 전용)
- 실물 불량 분석, 반품 처리 시스템 연동
