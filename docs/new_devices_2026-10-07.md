# 새 부품(LM5146, BQ25895) 어려운 문의 측정 (2026-10-07)

설계 점검을 넓힌 개선(소프트 스타트·최소 온타임·LDO 열·오프셋, [architecture.md](architecture.md))이 **처음 보는 부품**에서도 통하는지 보려고,
TI 데이터시트에서 가장 어렵다고 판단한 두 부품으로 문의 4건을 만들어 LLM 모드로 측정했다. 맞은 것과 틀린 것을 모두 적는다. 원자료는 `docs/feasibility/results/new_devices_llm.jsonl`.

## 한계 (먼저 읽을 것)

- 문의는 4건이고 각각 **1회** 측정했다. 같은 문의라도 다시 돌리면 달라질 수 있다.
- 채점은 문의를 쓴 쪽이 직접 했다 (작성자 = 채점자). 채점 기준(7항목)과 정답은 **측정 전에** `data/eval/eval_new_devices.jsonl`에 적고 커밋(`2469149`)했다. 정답 숫자는 부품 카드 값과 계산으로 다시 구해 `tests/test_eval_new_devices.py`가 대조한다.
- **카드 노트가 정성 항목의 점수를 올렸다.** 부품 카드(`data/parts/LM5146.yaml`, `BQ25895.yaml`)는 문의보다 먼저 내가 데이터시트에서 옮겨 적었고, 노트에 히컵 주기(400 kHz에서 0.32 ms / 20.5 ms), 감시 타이머 동작, D+/D− 판별 표가 들어 있다. 특히 Q-1의 3번(히컵 주기)은 카드 노트의 숫자를 그대로 쓴 쉬운 항목이었다.
  반대로 정답 계산(RILIM, 최대 듀티, IINMAX, TS 문턱 저항)은 카드에 결과로 적어 두지 않았다.
- 도구 없는 LLM과의 비교는 하지 않았다 (약 2만 토큰, 승인 대기).
- 일부 정답은 데이터시트가 직접 주는 값이 아니라 추정이고, 정답과 채점 기준에 그렇게 적었다: Q-3 "덮어써지는 시점"(REGN 220 ms, DCD 500 ms에서 추정), Q-4의 27/31 °C(103AT 두 점으로 맞춘 β로 추정, 데이터시트에는 온도표가 없음), Q-2의 750 kHz 최대 듀티(표에 없는 주파수라 최소 오프타임 식으로 추정).

## 알게 된 것

1. **코드가 숫자를 준 곳은 맞았다.** LM5146은 전용 코드 없이 카드만 만들었는데도 소프트 스타트(3.76 ms)와 최소 온타임(1.21 µs ≫ 60 ns) 점검이 그대로 작동해 미끼 2개를 모두 맞게 처리했다. 개선이 새 부품에도 통한다는 근거지만 2건뿐이다.
2. **모델이 스스로 계산해야 하는 숫자는 또 빠졌다.** RILIM, 최대 듀티, IINMAX(355/470), 입력 전력에서 충전 전류, TS 문턱 저항이 모두 정성적인 설명에 그쳤다. M-1~M-3의 결론("코드가 계산해 넘긴 숫자는 정확하고, 모델이 계산할 숫자는 빠진다")과 같다.
3. **틀린 내용이 나왔다.**
   - Q-1: VCC 14.4 V를 절대 최대 14 V 안이라고 썼다. 정격 점검(`ratings.py`)이 입력·전원 전압, 부하 전류, 출력 커패시터, ESR만 비교해서 VCC 같은 다른 핀은 보지 않는다.
   - Q-1: "인덕터를 키우라"는 권고는 골짜기 한계 방식에서 도움이 안 된다. 평균 한계 부하 = 골짜기 한계 + ΔIL/2라서 22 µH면 약 7.8 A에서 약 7.2 A로 오히려 낮아진다.
   - Q-3: 데이터시트 §8.2.12의 260 Ω 예시(ILIM 전압 0.4 V를 읽을 때의 입력 전류 모니터 값)를 470 Ω의 근거로 썼다. 분석 가설에는 IINLIM이 감시 타이머로 초기화된다고 썼는데, 데이터시트 p.31은 IINLIM이 초기화 대상에서 빠진다고 한다.
4. **재분석이 토큰의 68 %를 썼다.** Q-2(45,262)와 Q-4(48,355)는 재분석 3회로 검수 미통과로 끝났다. 계산 도구가 맞지 않는 부품에서 모델이 `value=30 > 29` 같은 값 대조 테스트를 억지로 만들어 방향 오류와 자기 참조(경계가 값과 같음)가 재발했다. 고객 답변 품질에는 큰 영향이 없었다.
5. 설계 점검 문구에 `1.21e+03 ns`처럼 큰 값이 서식 없이 나온다.
