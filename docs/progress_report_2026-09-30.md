# FAE Agent 진행 보고서 (2026-09-29 ~ 09-30)

작성일: 2026-09-30 · 대상 독자: 프로젝트 팀원·멘토 · 배포 마감: 2026-10-07(수)

## 1. 한 줄 요약

**실제 TI 부품 6종의 데이터시트로 문의 접수부터 사람 승인까지 도는 웹 앱(Django + React + Docker)을 로컬에서 완성했고, AWS 배포(10/5 예정)만 남았다.**
계산과 시뮬레이션을 함께 쓰는 검증이 연산증폭기에서 처음 실제로 동작했다. 반면 새 부품 12건 측정에서 원인 1순위는 6/9였고,
검수를 통과하지 못한 3건이 토큰의 49%를 썼다. 고쳐야 할 점은 이미 원인까지 확인했다 (§6).

| 항목 | 상태 |
| --- | --- |
| 웹 앱 (frontend, backend, worker, db, redis) | 로컬 완성. 재시작 후에도 승인 대기 유지, nginx 비밀번호, 접수 분당 10회 제한 |
| 실제 부품 데이터시트 | 3종 → **6종** (TPS7A20, LM2596, LMV321A + TPS7A02, TPS54331, LM358) |
| 계산 도구 / 시뮬레이션 회로 | 11종 / 2개 (연산증폭기 주파수 응답 추가) |
| 테스트 | 코어 95개 통과(1개 건너뜀), 백엔드 15개 통과 |

## 3. 시스템 구성

```text
브라우저 → frontend (nginx + React) ─ /api ─→ backend (Django) ─→ db (Postgres: 티켓·실행·진행 상태)
                                                   └─ 작업 전달 ─→ redis ─→ worker (Celery: LangGraph 실행)
                                                                                └→ OpenAI (llm 모드만), ngspice, 문서 검색
```

처리 흐름 (기술 문의): 접수·분류 → 근거 검색 → 원인 가설 → 계산·시뮬레이션 테스트 → 검수(최대 2회 재분석) → 답변 초안 → **사람 승인**.
품질 클레임은 접수 후 정격 점검(고객 값 대 데이터시트 한계)과 반품 자료 체크로, 배송·기타는 바로 답변 초안으로 간다.

- **mock과 llm:** 규칙만으로 도는 mock(토큰 0, 테스트용)과 OpenAI를 부르는 llm 모드가 있다. 계산·검수·승인은 두 모드가 같다.
- **MCP:** 도구를 MCP 서버 4개(계산, 문서 검색, ngspice, 티켓)로 노출했고 새 도구도 MCP로 동일한 결과가 나오는 것을 확인했다.
  다만 웹 앱과 측정은 함수 직접 호출(`local`) 모드로 돈다. MCP 경유 실행은 선택 사항이다.
- **접근 보호:** nginx 비밀번호, 문의 접수 분당 10회, 하루 토큰 상한(llm 모드). HTTP에서는 비밀번호가 읽히므로 인터넷 공개에는 HTTPS가 필요하다.

상세는 `docs/feasibility_report.md`. 결론은 "조건부 가능, 가치는 정확도가 아니라 근거와 계산 숫자가 붙은 초안을 사람이 승인하는 것"이다.

| 질문 | 결과 |

### 4.3 연산증폭기 계산·시뮬레이션 추가와 재측정 (H-A1, 같은 문의 네 번)

| 실행 | 토큰 | 재분석 | 테스트 | 정답 숫자 |
| --- | --- | --- | --- | --- |
| 도구 없음 (원래) | 17,456 | 1회 | 없음 | 0/2 |
| 계산 도구 추가 | 12,478 | 0회 | 재현만 | 2/2 |
| 계산 + 시뮬레이션, 수정 전 프롬프트 | 28,428 | 2회 | 5단계 | 2/2 |
| 계산 + 시뮬레이션, 프롬프트 수정 후 | 13,796 | 0회 | 3단계 | 2/2 |

- 계산 100 kHz·4.472배·0.894 Vpp, ngspice 99.99 kHz·4.472배·0.894 Vpp. 차이 0.01% 안팎 (Windows와 Docker의 ngspice가 동일).
- 수정 전 프롬프트에서 재분석이 늘어난 원인: 재현 테스트의 출력 진폭 기대 범위를 `0.18 Vpp`로 잘못 잡았고, 해결책으로 "이득을 낮춤"(200 kHz에서 이득 비율 0.707 < 목표 0.95)이 불충분했다. 프롬프트에 역산식을 넣자 재분석이 0회가 됐다.
- **각 1회 표본이라 재분석 감소가 프롬프트 덕인지 변동인지는 단정할 수 없다.**

## 5. 잘 된 것

- 데이터시트의 숫자를 답에 실어 준다: 절대 최대·권장 한계와 출처(쪽수), 계산값(소모전력, 접합 온도, 대역폭).
- 고객의 틀린 전제를 부품 카드로 정정한다: "IQ 25 nA면 전류 여유가 많다", "큰 커패시터가 더 안정적", "LM358은 레일 투 레일".
- 검수가 불충분한 해결책과 무의미한 테스트를 잡아 되돌린다 (정격 초과 누락, 이득만 낮춘 해결책 등).
- 계산과 시뮬레이션의 교차 확인이 동작한다 (연산증폭기 이득 0.005% 이내 일치).
- 부품 카드 값은 페이지를 이미지로 열어 표의 최소·전형·최대 열을 직접 확인했다.

## 6. 발견한 문제와 조치

| 문제 | 상태 |
| --- | --- |
| **검수 미통과 3건의 공통 원인:** `check_value`로 손계산 재현 테스트를 쓰면서 기대 범위 방향을 틀림 (한계 미만인데 min, 초과인데 max). 검수 지적은 정확한데 LLM이 3번 못 고침. 정답 가설인데도 내부 메모가 "가설과 불일치"로 검토자를 오도 | **미해결.** 프롬프트 표와 검수 힌트 추가 제안 (보류) |
| 슬루율이 진짜 원인일 때 가설에 넣지 않음 (N-A2). 재현 기대 범위가 0~1이라 항상 통과했는데 검수가 못 잡음 | 미해결 |
| 정격 점검이 입력 전압 조건만 비교해서 서지(32 V > 30 V)를 못 잡음 (N-L1). "IC가 죽는다"는 문의가 품질 클레임 경로로 감 | 미해결 |
| 답변에 지어낸 참고 계산 (N-L3: 고객 조건이 아닌 12 V, 1 MHz 가정) | 미해결 |
| 연산증폭기의 입력 신호 전압을 공급 전압으로 오인해 "권장 최소 3 V 미만" 경고 (N-A3) | 미해결 |
| 답변 인용에 내부 파일명(`[tps7a02.pdf p.19]`) 잔존 | 미해결 (부품 카드 경로는 수정함) |
| 규칙 기반(mock) 접수가 "전원 36V", "전원 ±15V" 표현을 못 읽음 | 미해결 (LLM 접수는 읽음) |
| 이전에 발견해 **고친 것:** 테스트 오류 뒤 테스트를 전부 비운 채 통과, 연산증폭기 계산 도구 부재, 재현 테스트가 자기 값으로 통과, 부품에 안 맞는 도구 사용, `bw_hz`가 결과 안쪽에만 있어 기대 범위로 못 찾음 | 수정 완료, 테스트 추가 |

## 7. 이번 단계에서 스스로 바로잡은 것

- 부품 카드 값 3건이 틀렸다가 표를 이미지로 확인해 바로잡았다: LM358 출력 전류(최소 20/전형 30 mA), TPS54331 전류 제한(최소 3.5/**전형** 5.8 A), TPS54331 UVLO 3.5 V는 최대 열 값.
- 토큰 예상이 한 번 빗나갔다 (연산증폭기 시뮬레이션 재확인: 예상 1.3만~2.2만, 실제 2.84만).
- 자동 채점이 "3 mV"를 "3 V"로 인정하는 오류를 발견해 직접 다시 셌다 (19/28 → 16/28).
- "통과하지 못한 부품은 배포에서 뺀다"고 했지만 **측정 전에 기준을 정하지 않았다.** 지금 제안할 기준은 §8에 있다.

## 8. 한계

- 문의 작성자, 시스템 조정자, 채점자가 같은 사람이다. 실제 고객 문의가 아니다. 블라인드 문의 30건 이상이 필요하다.
- 표본이 작다 (새 부품 기술 문의 9건, 같은 문의 반복 각 1회).
- 검수 규칙과 프롬프트를 처음 3종의 실패 사례를 보고 고쳤다. 새 부품 측정이 그 일반화를 처음으로 본 것이고 결과는 §4.4다.
- 새 부품 12건에는 **도구 없는 LLM 대조군을 돌리지 않았다** (약 2만 토큰 예상).
- 시뮬레이션은 회로 2개(부하 스텝, 연산증폭기 주파수 응답)뿐이고, 지난 검증에서 LLM 테스트 157단계 중 5단계(3%)만 썼다. 실제 TI IC 모델은 암호화되어 쓸 수 없다.
- 웹 앱은 mock에서 전체 흐름을, llm에서 문의 4건을 확인했다. AWS에서는 아직 돌려 보지 않았다.
- 새 부품 측정은 웹 앱이 아니라 별도 실행기로 했다 (같은 `fae_agent` 코드).
